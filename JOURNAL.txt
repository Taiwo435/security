## 2026-06-25 (Day 7)

### What we did:
- Research day: FGAC audit logging user experience analysis
- Spun up FGAC cluster, fired 9 test scenarios, documented findings
- Created RESEARCH_USER_PERSPECTIVE.md

### Key findings:
- One GET _cluster/health → 2+ audit events (fragmentation)
- No correlation ID linking events from same request
- _cat/indices → 4+ transport events
- COMPLIANCE_DOC_READ logs actual sensitive field VALUES (PII hotspot)
- INDEX_EVENT fires for flush, create, delete alike (useless signal)
- Our single-event design avoids all these problems

## 2026-06-26 (Day 8)

### What we did:
- Implemented request body logging with sensitive header exclusion
- Implemented ignore-users and ignore-requests filtering
- Implemented index resolution (wildcards → actual indices via IndexNameExpressionResolver)
- Implemented bulk request handling (per-sub-operation events when resolve_bulk_requests: true)

### Code changes (AuditActionFilter.java):
- Reads headers from ThreadContext, strips Authorization via WildcardMatcher
- Extracts body from SearchRequest.source(), IndexRequest.source(), UpdateRequest.doc().source()
- Early-return for internal:* actions, ignored users, ignored requests
- Index resolution with try/catch for cluster state readiness
- BulkShardRequest iteration for per-item audit events

### Flow:
- REST wrapper stashes headers in ThreadContext
- Request moves to transport → AuditActionFilter fires
- Filter pulls headers from ThreadContext + body from transport request
- Both go into single audit event
